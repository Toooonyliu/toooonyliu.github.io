Building with Claude & Codex

Making a real recording
work on the web.

Duowen turns recordings into transcripts people can review and share with AI. My biggest ask for the coding agents was to find a transcription tool, get it running, and connect it to a public website.

Research the tool

What does a free skill actually run?

I asked the agents to read the source behind transcription skills. That showed me where the instructions ended and the actual speech recognition began.

Connect the parts

The backend has a specific job.

The agents helped me map the upload path. Vercel hosts the website and server endpoint. That endpoint keeps the API key on the server and asks Deepgram to transcribe the file.

  1. 📎Browser

    Select an audio or video file

  2. ⚙️Vercel API

    Forward the transcription request

  3. 〰Deepgram Nova-3

    Return words, speakers, and times

  4. ✎Duowen editor

    Read, replay, and correct

Files over 4 MiB take a private Vercel Blob upload path before transcription. That path is implemented and still needs a live large-file test.

Try, debug, decide

Two routes. Different work to maintain.

Local experiment · WhisperX

A crash became a working short-file test.

WhisperX turns speech into timestamped text on a computer. On my Intel Mac, the agents traced incompatible packages and an OpenMP runtime conflict. Compatible versions and a corrected runtime produced text from a real 90-second clip. Speaker labels were still unverified.

Live site · Deepgram + Vercel

Recognition runs on the provider’s servers.

I chose Deepgram to avoid maintaining a model server. Claude identified the build setting needed to enable it in the deployed website. Speech usage is billed by duration, with hosting and storage costs separate.

Refine the interface

I reviewed the workflow. The agents made the changes.

  • Make the handoff visible. I asked Codex to move Send to AI from the overflow menu into the recording header.
  • Keep long projects manageable. I asked for an included-recordings list, one Markdown attachment, and a separately editable prompt.

The in-person playtest reinforced the review step. People wanted to see who said what and when, and spot mistakes before sharing the text with AI.

Evaluate the result

Check what the code actually does.

Verified

A real 90-second upload returned two speaker labels and supported click-to-play. Ten synthetic transcripts stayed in order in a combined Markdown export.

Next test

Take a full class through transcription, correction, and AI handoff. Check word errors, speaker changes, and whether people can find and fix mistakes.

My role was to choose the task, review the output, and test with people. Claude and Codex helped me research, implement, debug, and check the software.
