Building the transcription backend

I used AI to compare speech tools, debug local inference, and connect a deployed API. The test was whether a new file could travel from browser upload to a transcript I could verify against the audio.

Define

What the website needed to do

Accept an audio or video file from a class or discussion. Return text, timing, and speaker labels. Let me review and correct the result before bringing it to a chat.

Agent skill
Instructions or a wrapper that helps an agent call a tool.
Speech engine
Runs recognition on the file. WhisperX can run locally.
Speech API
Lets the website request hosted inference. Deepgram runs the model and returns the result.

What I tried and what I priced

Tested locally

WhisperX

AI helped trace an Intel Mac dependency and OpenMP conflict. The repaired setup produced timestamped text from a 90-second clip. A browser upload also returned text, but heard “Duowen” as “Duane.” Speakers remained unassigned.

Cost No per-minute API fee. My computer supplied the compute and I maintained the runtime.

Shipped on Vercel

Deepgram Nova-3

Deepgram handled recognition, timing, and speaker diarization in one API response. That gave me a deployable upload flow without running the model server myself.

Cost Speech recognition is metered by audio duration. Hosting and storage are separate.

Deepgram pricing ↗

I also compared AssemblyAI and OpenAI on paper. AssemblyAI’s Universal-2 and Universal-3.5 Pro cost $0.17 and $0.23 per audio hour respectively with speaker diarization. AssemblyAI pricing ↗

Deliver

Test the whole path

I used Claude and Codex to build and check the path from upload to playback and export. A real 90-second upload on the live site returned two speaker labels. Separately, ten synthetic transcripts let me check that the project export kept every file in order.

I still want to evaluate word and speaker errors on full classes, then verify whether a chat’s follow-up holds up against the recording.
