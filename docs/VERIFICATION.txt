Mibly｜实际验证记录
日期：2026-10-18
对象：mibly-redcowork-v2（服务端调用平台大模型的版本）

已通过（本地）
1. npm test：30/30。
   - 22 项原有测试：关键词规则、作者与否定硬条件、私密范围、校验器（新增：理由长度、追问必须是问句、不含链接）。
   - 8 项服务端测试，模型回复为脚本化内容：
     · 朋友记录内容以服务端为准，浏览器篡改的留言被覆盖；他人私密、伪造的朋友记录、隐藏好友、未接受的申请都被排除；本人新发的记录被接受。
     · 发给模型的候选不含照片、受众标记和 authorId；点名的朋友在调用前已过滤；today 传入。
     · 伪造的引用、不存在的 ID、不符合点名条件的记录被丢弃并计数，不做修补。
     · unresolved 只保留用户原话片段；代码识别的“适合两个人”一定保留。
     · 追问必须是问句，否则换成固定问句。
     · 非 JSON 回复重试一次；两次都失败返回明确错误。
     · 没有候选时不调用模型。
     · 开发替身全程标为 local。
2. npm run build：TypeScript 与 Vite 构建通过。
3. npm run check:runtime：28 个受保护运行时文件完整。
4. 浏览器端到端（Playwright + Chromium，Express 服务端）：
   - 脚本化模型：标签“✦ AI 检索”；“Maya 带爸妈去的那家”返回 1 张卡片，含 AI 理由、原文引用和“AI · 用时 1.2 秒”；“Maya 吃过的日料，适合两个人吗”返回 1 张 Kura 餐厅卡片（2 条 Maya 的记录）和“原帖里没写，不做猜测：适合两个人”；“汽车保养”显示没找到；“那个”显示模型的追问。
   - 开发替身：标签“开发替身 · 关键词”，结果标“仅关键词匹配，未使用 AI”。
   - 没有 guard_sdk：标签“AI 未连接”，搜索时提示并提供“改用关键词检索”。
